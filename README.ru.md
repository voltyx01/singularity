# Singularity

> English: [README.md](README.md) · **Если вы ИИ, сначала прочитайте [AGENTS.md](AGENTS.md).**

Маленький мост без зависимостей между **ИИ-оркестратором (Claude Code) и безголовыми рабочими агентами (Google Antigravity CLI `agy` с моделями
Gemini)**. Оркестратор планирует, ревьюит и владеет общим кодом, рабочие параллельно переписывают сотни файлов, а вы смотрите за всем в
живой веб-консоли. Всё это обычные файлы и около 800 строк Python на стандартной библиотеке.

Мост появился при переносе мода для Minecraft на 1000+ файлов между версиями (чтобы код компилировался, достаточно мало, а чтобы вёл себя так же,
как оригинал, нужно много), но ничего специфичного для Minecraft в нём нет: подойдёт любая большая миграция, рефакторинг или аудит, где есть команда сборки или тестов.

## Принцип работы

1. **Задачи** лежат в `bridge/TASKS.md`: таблица, одна папка (scope) на задачу, статусы `OPEN → CLAIMED → REVIEW → DONE / RETURNED`.
2. **Общий код** (регистры, базовые классы, конфиги) пишет оркестратор. Рабочие его не трогают, а просят через `bridge/REQUESTS.md`.
3. `orchestrate.py` берёт OPEN-задачу, запускает `agy -p` с промптом из `bridge/RULES.md` + `GATEWAY.md` (+ заметки по задаче), потом **сам независимо**
   проверяет результат через `check.py` и не верит отчёту агента. Если есть ошибки, он повторяет запуск со списком ошибок (до `--max-rounds`), потом `RETURNED`.
4. Чистая сборка не значит правильное поведение, поэтому после неё идёт `REVIEW`: оркестратор сравнивает дифф с оригиналом.
5. `audit.py` запускает агентов только на чтение: они сравнивают новый код с оригиналом и пишут отчёты `bridge/REPORT/AUDIT-<unit>.md`.
   Находки считаются гипотезами, и каждую оркестратор проверяет в коде.
6. `auto_resume.py` ждёт, пока вернётся квота модели, и перезапускает цикл. Пока цикл идёт, токены оркестратора не тратятся.

### Зачем шлюз (`gw.py`)

Агент `agy -p` не может спросить разрешение. Правила разрешений сверяют точную строку команды, и любая другая команда обрывает запуск. Поэтому у агента
одна заранее разрешённая команда `python -I tools/gw.py <агент>`. Он пишет JSON-запрос в `bridge/gw/<агент>.json`, шлюз выполняет только белый список
операций (`check`, `grep`, `commit`, `post`, `inbox`, `diffstat`) и пишет ответ в `bridge/gw/<агент>.out`. Коммитить можно только пути из `commit_allow`.

### Чат

`bridge/chat.jsonl` (только дописывается) и `tools/chat.py`: `post`, `inbox`, `read`, `watch`. Человек пишет оттуда же через `tools/console.py`
(слушает только `127.0.0.1`). Claude Code можно будить новыми сообщениями без опроса: запустить
`CHAT_INBOUND_ONLY=1 python -I tools/chat.py watch --to claude` под инструментом Monitor.

## Быстрый старт

```bash
git clone https://github.com/voltyx01/singularity.git && cd singularity
cp singularity.example.json singularity.json     # укажите check.cmd, work_dirs и т.д.
agy                                              # один раз войти; API-ключи нигде не используются
python -I tools/check.py core                    # ваша команда сборки, отфильтрованная по одному scope
python -I tools/orchestrate.py --dry-run         # список OPEN-задач
python -I tools/orchestrate.py --only T001       # одна задача от начала до конца
python -I tools/console.py --open                # смотреть вживую
```

Подробнее: [docs/SETUP.md](docs/SETUP.md), устройство: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Инструкции для ИИ

- Оркестратор (Claude Code и т.п.): [docs/ORCHESTRATOR.md](docs/ORCHESTRATOR.md)
- Рабочие агенты (`agy -p`): [docs/WORKER.md](docs/WORKER.md) и проектные `bridge/RULES.md`, `bridge/GATEWAY.md`, которые скрипты подставляют в каждый промпт.

## Безопасность

- **В репозитории нет и не читаются никакие ключи.** `agy` входит через собственный логин. `.gitignore` исключает логи чата, отчёты, файлы шлюза,
  локальный конфиг и типичные имена секретных файлов.
- Всё, что попадает в промпт, уходит стороннему сервису: не кладите секреты и личные данные в `RULES.md`, заметки и открытый для агентов код.
- Шлюз и консоль — защитные ограждения, а не песочница. Смотрите, что коммитят рабочие.
- Флаги `agy` меняются между версиями; адаптировать нужно одно место: `tools/common.py::agent_command`.
